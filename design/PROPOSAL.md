# EIV — 项目提案

## 一句话描述

EIV 是一个独立、事后验证 AI agent 链上执行完整性的基础设施。

**通俗版：** 检查 AI 有没有"照章办事"的审计系统。

---

## 解决什么问题？

### 场景

你让 AI 帮你在链上执行一笔交易（比如转账 100 USDC 给张三）。你签了授权，AI 去执行了。

**但是，AI 实际执行的可能和你说的不一样：**

| 你说的 | AI 可能做的 |
|--------|-----------|
| 转给张三 | 转给了李四 |
| 转 100 USDC | 转了 200 USDC |
| 3 点前完成 | 4 点才完成 |
| 用完就关授权 | 留了一个无限授权 |

### 问题

**谁来检查 AI 做得对不对？**

- 用户自己检查？→ 太复杂，看不懂
- 平台检查？→ 用户不信平台
- 政府检查？→ 太慢，而且 Web3 没有政府

### 解决方案

**EIV：独立的第三方审计。**

```
用户签名 ──▶ AI 执行 ──▶ EIV 检查 ──▶ 结果上链
                              │
                              ▼
                    "AI 做得对不对？"
                    PASS = 没问题
                    FAIL = 有问题（附详细说明）
```

---

## 技术方案

### 核心逻辑

EIV 做的事情很简单：

1. 拿到用户的"授权书"（IntentSpec）
2. 拿到 AI 的"执行记录"（ExecutionTrace）
3. 逐条对比，找出差异
4. 输出"审计报告"（verdict + violations）

### 为什么能做到"独立"和"确定性"？

- **独立**：EIV 不属于任何平台，它是第三方
- **确定性**：同一个输入，永远得到同一个输出（不会因为"心情好"而变）

### 为什么选择链上存证？

- 结果写到链上，**任何人**都可以验证
- 不能篡改，不能删除
- 符合 Web3 的"不需要信任，可以验证"哲学

## 预期成果

### Demo Day 演示

1. 用户在 Dashboard 上看到"待验证"的交易
2. 点击"验证"按钮
3. EIV 引擎检查交易
4. Dashboard 展示结果：
   - 绿色 PASS = AI 做得对
   - 红色 FAIL = AI 做得不对 + 详细说明
5. 结果上链，任何人可以验证

### 评审加分项

- 零依赖（只用 Python 标准库）
- 确定性（同一个输入永远同一个输出）
- 符合 ERC-8004 标准
- 团队协作清晰（4 个仓库，各司其职）
